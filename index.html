Professional Self-Assessment

Completing the Computer Science program has allowed me to transform from an independent student to a developer that understands how to collaborate alongside others, communicate in ways that are understandable for many audiences, and create software that doesn’t just function, but functions efficiently and securely.

This program allowed me to understand the importance of working in a team environment and exactly how to do that. In CS 250 (Software Development Lifecycle), I learned different team environments that I may encounter in the Computer Science field, such as agile or waterfall-based work environments. My communication skills were further improved in CS 255 (System Analysis and Design), where I not only had to work through complex problems to design a cohesive project, but also explain my choices along the way. My technical communication has also been improved through this program, specifically by CS 340 (Client/Server Development) and CS 499 (Computer Science Capstone). In both of these courses, I worked on projects that involved explaining my code and decisions technically in detail. I am also proficient in using Git after working through CS 465 (Full Stack Development).

As I’ve worked through the program, I have grown more accustomed to working with data structures and algorithms. This has influenced my enhancements below as I’ve started working more efficiently, understanding that code can have more than one solution. CS 300 (Data Structures and Algorithms) was key to me practicing and becoming more comfortable with different data structures.

Database integration is an element that I like to add to most of my projects now. It was through projects done in IT 235 (Database Design) and CS 465 that I became more comfortable working with databases, understanding that a good database starts with its design more than anything. Software engineering is another strength I have improved through courses, such as CS 465 and CS 360 (Mobile Architecture and Programming). These courses improved how I handled modularity in my projects as well as error handling and keeping code up-to-date.

Security was a reoccurring theme all throughout this program, so it became an important theme in my code as well. I learned that secure code does not have an “end date”. Security begins with checking for vulnerabilities and continues throughout, whether it is input validation or excluding hard-coded materials. CS 305 (Software Testing) was a course primarily teaching quality control of code, but it also helped me improve my input validation and understanding how easy it can be to leave code unsecure. CS 320 (Software Security) was also a major improvement point for me in this journey as it taught me more about vulnerabilities in code and how security concerns can be introduced into your code through APIs.

Below, I have included three artifacts that show my improvement in three distinct categories: software design and engineering, algorithms and data structures, and databases. The first artifact will display how I can take a functional application and improve it not only for future developers that may come to work on it, but users as well. The second artifact is an example of my understanding of efficiency in code and object-oriented programming. The last artifact displays my deep understanding of databases and how to code an application that can communicate with a database, but still allow personalization to the user.

Artifact 1: Software Design and Engineering

Appointment Tracker

This project is a local application that allows users to add, edit, and delete appointments from a simple interface.

The artifact was created in the CS 320 course. This project was created in October 2025. The original purpose of this artifact was to be able to manage appointments through creating, updating, reading, and deleting using Java. The intended priority of this project was ensuring all features were fully tested through JUnit tests.

I selected this item to display my skills in software engineering and design because I saw a lot of opportunities to improve the current design, which was largely a simple backend with testing. I wanted to be able to create a project using a stack I have not tried before, which was JavaFX with Maven and SQLite. Since this is a full stack application now, it shows my ability to connect a backend with a frontend and have reliable communication with a database. It also displays my skills in defensive programming as it does have strict requirements for appointment handling. The artifact was improved by giving the user a UI to interact with. It also was made more efficient by transforming from a hashmap to a local database. Lastly, it is now more developer-friendly because I fully commented the program where there weren’t any comments before.

I do think I met the course outcomes I planned to meet in the original plan. In the original plan, I detailed that I would be making this project more collaborative and use better security practices. By commenting and making the code modular, this does prep the project to be worked on by developers in the future. I also moved to a database architecture with a controller-service-repository architecture to protect its data. I also ensured there was validation throughout the project. I think this project also exemplifies the fourth course outcome since I am using well-founded techniques to build this project. It is a simple application, but to prepare it for further growth, I did develop it with the future in mind.

As I was enhancing this artifact, I quickly realized that my plan was not as fleshed out as it could have been. I could have planned the architecture a bit better. It made me realize how important the planning phase is in software development and how much easier the process could have been if I spent more time planning the overall architecture I wanted and how I would use the code I had already written. Most of the backend was easy to set up. I did not feel like I was running into challenges until I started working on the frontend, but that is more so due to me learning more about JavaFX and how to connect to the backend from there. As I was walking through my code again, I realized I had coded too defensively and accidentally coded validation branches throughout multiple parts of the code, to which I fixed as well.

Artifact 2: Algorithms and Data Structures

Rescue Animal Project

This project is a Java-based rescue animal application designed for the user to manage animal records within the rescue.

This artifact was created in IT 145 in February 2025. This was an application created to manage a rescue animal service. Its main priorities were to be able to create new animals, reserve animals, and print the animals that were in the system.

I selected this artifact for my ePortfolio because it shows my improvement in understanding code efficiency, specifically in algorithms and data structures. Upon initially completing this application, it functioned but not as well as it could, which is what I worked on enhancing for this artifact. I transferred from an ArrayList to a HashMap to improve search features that already existed, such as checking whether a name already existed in the system. I also improved this artifact by adding validation to the inputs where there was none before as well as fixing loops that would run infinitely. The only reason these loops were missed when I initially created this project was due to a “return” statement that was always triggered.

In my initial proposal, I said this artifact would align with the third course outcome that states that I would design and evaluate computing solutions for a given problem. I believe this was accomplished as well as a couple other course outcomes. I also think my enhancements covered the first and last course outcomes as well since I improved the commenting for future developers and added validation.

As I was enhancing this artifact, I was following the pseudocode I wrote in my initial proposal. I learned that there is often multiple solutions to one problem. During my development, I found even more efficient ways to tackle a problem. In this specific application, the only challenge I faced was having to refactor all the methods to work with a HashMap instead of an ArrayList. Some loops would also often print an animal’s details then also print that “no animals were found”, which was an easy fix.

Artifact 3: Databases

Rescue Animal Dashboard

This project is a Python-based dashboard application that allows users to interact with data from rescue services to find animals that meet their criteria.

This artifact was made in March, 2026 during CS 340. It was initially a Jupyter Dash notebook and Python CRUD module. Its purpose was to provide a frontend dashboard for users to be able to find information on rescue animals, including a pie chart and geolocation data.

I included this artifact in my ePortfolio because I saw a lot of improvement in the CRUD methods as well as how the dashboard communicates with the database. In this artifact, it showcases my skills in creating efficient code that can be evolved over time. Along with this, it shows my understanding of CRUD features due to exception handling. I improved this artifact by first removing the hardcoded data, which was seen in the “rescue types” that were premade queries. I added dynamic filtering so that users can select the specific animal they are looking for with options for type, breed, sex, and age. With that, I also changed the radio buttons that were used for the rescue types to be dropdowns and integer inputs. I also fixed the CRUD methods to anticipate missing data and throw exceptions with proper error messages. Lastly, I cleaned up the comments since there were a lot of “FIXME” comments as well as unused code. This artifact was also changed from a Jupyter notebook to a Python file for the dashboard as well as the CRUD module.

In my initial plan, the third course outcome was my intended mark for this artifact. I believe I met this outcome whenever I decided to move from the hardcoded data to a more dynamic filtering system. I had to evaluate the tradeoffs for this change. I think I also met the second course outcome because I did change this artifact to be more user-friendly by allowing users to select exactly what animal they were looking for. This also future proofs this project as well.

As I was improving this artifact, I learned more about MongoDB and authentication. During improvement, I moved from a Jupyter Notebook to a Python file in VS Code. Because I was working off my local computer instead of the online environment, I had to adjust my MongoDB server to accept authentication.
